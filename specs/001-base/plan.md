# Plan — Spec 001: Base del monorepo

Parte de `specs/001-base/spec.md` (Estado: aprobada). Cumple `docs/constitution.md` y `AGENTS.md`.

## 1. Visión general

- Monorepo pnpm con dos paquetes de workspace: `apps/web` (Astro) y `apps/control` (React + Vite).
- Las herramientas transversales viven en la raíz: TypeScript, ESLint + Prettier, Vitest (con proyectos por app), Playwright (un único config con un proyecto por app) y scripts Node sin dependencias en `scripts/`.
- Lighthouse CI vive en `apps/web`, que es la única app auditada.
- Un solo navegador: el `chrome-headless-shell` que instala Playwright junto con su Chromium. Lo usan tanto `pnpm test` como Lighthouse CI. El `chrome.exe` completo no se usa porque no arranca en la máquina del desarrollador (ver riesgos).
- La lógica comprobable (validar el entorno, localizar el navegador, títulos de página) va en funciones puras con tests en Vitest. Las páginas solo pintan.

Sin `only-allow` ni `@astrojs/check`: lo primero se resuelve con un script propio sin dependencias y lo segundo no lo pide la spec.

Decisión del usuario (T7): la telemetría de Astro queda desactivada en el proyecto de forma versionada y sin dependencias. Los scripts `dev`, `build` y `preview` de `apps/web` van precedidos de `ASTRO_TELEMETRY_DISABLED=1`, el mecanismo que indica la documentación de Astro para CI y scripts. Para que `VAR=valor comando` funcione igual en Windows (`cmd`) y en Linux, `pnpm-workspace.yaml` activa `shellEmulator: true`, el intérprete portable integrado en pnpm (en `.npmrc` no tiene efecto con pnpm 12). Alternativas descartadas: `astro telemetry disable` solo cambia la configuración del usuario en su máquina y no se versiona; `cross-env` es una dependencia nueva.

Decisiones de la validación (T11):

- **Finales de línea:** `.gitattributes` con `* text=auto eol=lf`, y los binarios marcados con `binary` (`*.png`, `*.jpg`, `*.webp`, `*.avif`, `*.ico`, `*.woff2`, `*.pdf`). Así cada clon tiene LF aunque Windows tenga `core.autocrlf=true`, que es lo que exige Prettier (`endOfLine: "lf"`).
  - Alternativa descartada: `endOfLine: "auto"` en Prettier. Dejaría el repo con finales mezclados según quién haga el commit.
- **Versión de Node estricta:** pnpm 12 no lee `engine-strict` de `.npmrc` (`pnpm config get engine-strict` devuelve `undefined`). Pasa a `engineStrict: true` en `pnpm-workspace.yaml`, junto a `shellEmulator`, y se elimina de `.npmrc`. Si `.npmrc` queda vacío, se borra.
  - `preinstall` (check-env) sigue siendo la segunda barrera.
  - Si con Node 22 y `node_modules` ya instalado `pnpm install` no falla, hay que parar y preguntar al usuario.
- **Puertos separados (decisión del usuario):** `astro dev` sigue en 4321. La preview de producción de la web, que usan Playwright y Lighthouse, pasa a 4322 con `--strictPort`. Así un `pnpm dev:web` abierto no se confunde con la build que se prueba ni la reutiliza.

## 5. Lógica (pseudocódigo)

```
checkEnvironment({ nodeVersion, userAgent }):
  errors = []
  major = parseInt(nodeVersion.replace(/^v/, "").split(".")[0])
  if major !== 24: errors.push("Node 24 LTS requerido (>=24 <25); tienes " + nodeVersion)
  if !userAgent?.startsWith("pnpm/"): errors.push("Usa pnpm para instalar (pnpm install)")
  return errors

findHeadlessShell({ browsersDir, platform, entries }):
  dirs = entries filtered by /^chromium_headless_shell-(\d+)$/, sorted by number desc
  if dirs is empty: return null
  sub = { win32: "chrome-headless-shell-win64/chrome-headless-shell.exe",
          linux: "chrome-headless-shell-linux64/chrome-headless-shell",
          darwin: "chrome-headless-shell-mac-*/chrome-headless-shell" }[platform]
  return join(browsersDir, dirs[0], sub)   // on darwin the arch (x64/arm64) is resolved by the CLI

browserStatus({ executablePath, exists }):
  if executablePath && exists: return { ok: true }
  return { ok: false, message: "chrome-headless-shell de Playwright no encontrado" + (executablePath ? " en " + executablePath : "") + ". Ejecuta: pnpm browsers:install" }
```

Las tres reciben sus datos como parámetro: ni `process` ni `fs` dentro de la función (principio 3).

## 10. Riesgos

- Lighthouse en Windows puede dar avisos de limpieza de carpetas temporales sin que falle. Solo cuenta el código de salida.
- Comprobado en T7: en la máquina del desarrollador, el `chrome.exe` completo de Chromium 1248 (el de `chromium.executablePath()`) no arranca. Windows da el error "configuración en paralelo incorrecta" porque no encuentra el ensamblado `156.0.8078.4`. Sigue igual tras `playwright install --force chromium`. Una copia del exe en otra carpeta no da ese error. El `chrome-headless-shell` de Playwright sí arranca, y por eso `pnpm test` pasa. **Resuelto** por decisión del usuario: Lighthouse CI usa el `chrome-headless-shell` de Playwright en lugar del Chromium completo, y `check-browser` comprueba ese mismo ejecutable. Las puntuaciones, sobre todo la de Rendimiento, pueden diferir algo de las de un Chrome completo. El umbral ≥ 0.9 se mantiene igual.
